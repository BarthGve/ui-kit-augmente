# Gantt

`Gantt` shows tasks on a time axis: one row per task, a bar from its start to
its end date, a marker on today. It is read-only by default. With `editable`
and `onTaskChange`, bars can be moved and resized, with the pointer or the
keyboard, by whole zoom units (see [Editing](#editing)).

## Structure

```tsx
import { Gantt } from "@gouvfr-lasuite/ui-components";

<div style={{ height: "24rem" }}>
  <Gantt
    aria-label="Project schedule"
    tasks={[
      {
        id: "brief",
        name: "Write the brief",
        start: "2026-03-02",
        end: "2026-03-13",
      },
      { id: "review", name: "Review", start: "2026-03-25", end: "2026-03-25" },
      { id: "plan", name: "Plan the launch" },
    ]}
  />
</div>;
```

<Canvas of={GanttStories.Default} />

The chart is a single scroll box. The task column and the axis are sticky: the
list stays in place while the timeline scrolls horizontally, and the axis stays
on top while the rows scroll vertically.

**Give the chart a size.** It fills the width of its container and takes at
most the height of a sized parent (`max-block-size: 100%`), beyond which the
box scrolls. In a shrink-to-fit parent (a flex row item, `inline-block`, an
`auto` grid track) it collapses to no width: give it a width there, for
example `flex: 1` or `width: 100%`.

`aria-label` is required: it names the grid, which has no visible title.

## Data

```ts
interface GanttTask {
  id: string; // stable, unique
  name: string;
  start?: string | CalendarDate; // "YYYY-MM-DD"
  end?: string | CalendarDate; // inclusive
}
```

- **Calendar dates, not instants.** Dates are ISO days (`"2026-03-30"`) or
  `CalendarDate`s from `@internationalized/date`. No time and no time zone is
  involved, so a bar never shifts by a day across a daylight-saving change.
- **The end is inclusive**: a one-day task has `start` equal to `end` and is one
  day wide.
- Rows follow the array order. The component never modifies `tasks`.
- The axis starts on the first day of the locale's week (Monday in `fr-FR`,
  Sunday in `en-US`) before the earliest start, and ends with the week or the
  month of the latest end.

### Tasks without dates

A task with no dates, only one of the two, an end before its start, or a date
that does not exist (`"2026-02-30"`) keeps its row and its name, shows
"No dates" and draws no bar.

### Today

`today` sets the marker's day (default: today in the local time zone). The
marker is a line with a "Today" label, not drawn when today is outside the
axis. Pass a fixed `today` in tests and stories. The marker does not move at
midnight while the page stays open.

## Zoom

Day, Week and Month change the width of a day (and the axis labels). Week is
the default. Uncontrolled, `defaultZoom` sets the initial zoom. Controlled,
`zoom` decides and `onZoomChange` receives the requested zoom; the chart only
changes when the parent updates `zoom`. A zoom change from the control keeps
the left-most visible day in place; in controlled mode, as long as the chart
is not scrolled between the request and the parent's update (a request the
parent refuses is dropped once the chart scrolls). A `zoom` change that does
not come from the control keeps the scroll offset.

## Keyboard

| Key                       | Action                                                                  |
| ------------------------- | ----------------------------------------------------------------------- |
| `Tab`                     | Reaches the Day, Week and Month buttons, then the current task row once |
| `Shift+Tab`               | The same, backwards                                                     |
| `Enter` / `Space`         | On a zoom button, switches the zoom                                     |
| `Arrow Down` / `Arrow Up` | Focuses the next / previous task row, without wrapping                  |
| `Home` / `End`            | Focuses the first / last task row                                       |

The chart is one tab stop: `Tab` enters on the current row (the first one
initially, then the last row focused, by keyboard or by click) and the next
`Tab` leaves the chart. Moving to a row scrolls its bar into view. Arrow keys
with `Ctrl` or `Meta` are always left to the browser; with `Alt` or `Shift`
they edit the task when the chart is `editable` (see
[Editing](#editing)), and are left to the browser otherwise.

The focused row announces the task and its dates, formatted for the active
locale:

| Task         | Announcement (en-US)                                    |
| ------------ | ------------------------------------------------------- |
| Dated        | "Write the brief, from March 2, 2026 to March 13, 2026" |
| One day      | "Review, March 25, 2026"                                |
| Without date | "Plan the launch, no dates"                             |

Keyboard focus draws a ring around the visible part of the row, also in
forced-colors mode; there is no ring after a mouse click. The bars, the today
marker and the dense lower axis labels are hidden from assistive technologies:
the row's name carries the dates.

## Editing

<Canvas of={GanttStories.Editable} />

```tsx
const [tasks, setTasks] = useState(initialTasks);

<Gantt
  aria-label="Project schedule"
  tasks={tasks}
  editable
  onTaskChange={(id, change) =>
    setTasks((all) =>
      all.map((task) => (task.id === id ? { ...task, ...change } : task)),
    )
  }
/>;
```

| Prop           | Type                                                           | Default |
| -------------- | -------------------------------------------------------------- | ------- |
| `editable`     | `boolean`                                                      | `false` |
| `onTaskChange` | `(id: string, change: { start: string; end: string }) => void` | none    |

- **Controlled.** The chart never modifies `tasks`. An edit shows a preview
  (the bar at its new dates, a dashed outline at the old ones, a date chip),
  then calls `onTaskChange` **once**, when it is confirmed. Apply the change to
  your data: otherwise the bar goes back to its dates. A cancelled edit, or one
  that ends on the original dates, calls nothing.
- **Payload.** `start` and `end` are ISO calendar days (`"2026-03-09"`), the end
  inclusive, as in `GanttTask`.
- **Without `editable`** (the default) the chart is exactly the read-only
  chart: no handles, no shortcuts, the modified arrows left to the browser.
  `editable` without `onTaskChange` previews edits and reports nothing.

### Steps follow the zoom

| Zoom    | One step                                                                |
| ------- | ----------------------------------------------------------------------- |
| `day`   | 1 day                                                                   |
| `week`  | 7 days                                                                  |
| `month` | 1 calendar month, clamped to the month's last day (Jan 31 + 1 = Feb 28) |

A move keeps the length in days. Every step is counted from the dates the edit
started from, so one step forward and one back always returns to them (Jan 31,
not Jan 28).

### Limits

- **The end never goes before the start**: a task is at least one day long.
  The edit stops there and says "The end cannot be before the start".
- **The axis does not grow during an edit**: a task stops at the first or last
  day drawn, with "Limit of the chart reached". Confirm, then edit again from
  the new axis.
- A task without dates, or cut by the ten-year window, cannot be edited.
- **Right-to-left** (`dir="rtl"` on the chart or an ancestor, read once when it
  mounts): editing is not supported and `editable` is ignored.

### Pointer

- Drag a bar to move it; drag one of its edge handles (shown on hover and on
  the focused row) to change only that date. The bar jumps by whole steps.
- Each handle is a 24px-wide target (`handle-hit-size`) over the row's height.
  Under 72px a bar's handles shrink to a third of it, and a bar narrower than
  24px has none (it still moves): zoom in, or use the keyboard.
- Held near the edge of the visible timeline (48px), the box scrolls and the
  dates follow.
- Touch: a finger on a bar or a handle drags it; on the timeline or the task
  column it scrolls. There is no long press.
- `Escape`, a lost pointer (cancelled touch, another window) or leaving the
  window cancel the drag. While a drag runs, `Escape` is not passed on: in a
  dialog, the first `Escape` cancels the drag, the next one closes the dialog.

### Keyboard

On a focused task row of an `editable` chart:

| Key                          | Action                                                  |
| ---------------------------- | ------------------------------------------------------- |
| `Alt+Arrow Right` / `Left`   | Previews the task one step later / earlier (both dates) |
| `Shift+Arrow Right` / `Left` | Previews the end one step later / earlier               |
| `Enter`                      | Confirms the edit: `onTaskChange` is called once        |
| `Escape`                     | Cancels the edit: the dates are restored                |

`Alt` and `Shift` steps combine in one edit (to change only the start, move
then shorten the end). Moving to another row (`Arrow Up`, `Arrow Down`,
`Home`, `End`, `Tab`, a click) or leaving the window cancels the edit, then
navigates as usual. The row keeps the focus after `Enter` and `Escape`, and its
bar is scrolled into view after `Enter`.

`Alt+Arrow Left` / `Right` is history back / forward in browsers on Windows and
Linux. The chart keeps the key from the browser only when it edits (an
editable row with dates is focused): elsewhere the browser shortcut works.

### Assistive technologies

Editable rows expose the shortcuts (`aria-keyshortcuts`) and a short
instruction as their description. The row's name does not change during an
edit; a polite status region announces the new dates at each step, the limit
reached, the confirmed dates ("Write the brief rescheduled: March 9, 2026 to
March 20, 2026") and a cancel ("Write the brief: change cancelled, dates
restored"), in the active locale. Repeating the same limit is announced once.

Dragging has no pointer-only alternative without the keyboard (WCAG 2.5.7):
a pointer user who cannot drag edits the dates with the keyboard, or in your
own form.

## Size and performance

Every task is rendered, there is no windowing. Off-screen rows skip layout
and paint (`content-visibility: auto`), and grid lines are a background, not
one element per day, so the DOM grows with rows plus axis labels. The task
count is up to the caller and is not capped: `LongSchedule` (100 rows) is the
size checked; beyond a few hundred rows, measure with your data, and split or
page it if needed.

The drawn range is capped at about ten years (3660 days). A wider schedule is
windowed around today; bars are cut at the window's edges, and a task wholly
outside the window keeps its row and its announced dates but draws no bar.

Transitions are removed when reduced motion is requested.

## Later versions

Dependencies between tasks are additive: `id` is stable, `tasks` is never
modified, and the bar is a stable element (`.c__gantt__bar[data-task-id]`) in
its row. An edit does not move other tasks.
