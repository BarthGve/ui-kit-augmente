## The structuring facts
1. **Upstream #259 is not what the story's ACs describe.** Title "Filters major update", open since 2026-06-23, no comments. Four bullets: (a) filters take less space, (b) **filters are simply UI-kit buttons in their tiny format and no longer a dedicated component**, (c) overflow handled by **left/right arrow buttons** in addition to horizontal scroll, (d) filters can display an **icon** (inherited from buttons). The image shows a "Filter Bar": a row of compact pill buttons (icon + "Filter" + chevron), the first one active (blue tint), a **trailing reset icon button** (undo arrow) after the last filter, and two overflow variants with a floating round arrow button on the right or the left edge. **Nothing about loading, empty, open, tokens or `onReset`.** The story's ACs (states, tokens, `onReset`, loading/empty, keyboard) are the previous framing's own reading; the issue's visual changes (icon, arrows, bar-level reset, "no dedicated component") are **not in any AC**.
   - Shipped from #259: **nothing**. `git log` on `components/filter` and `components/search-filter` shows only four repo-move/merge commits (`72b3abb4`, `c8d1f06c`, `33311e33`, `9a50806e`). No icon prop, no overflow arrows, no bar component, no trailing reset (the reset is a row inside each popover).
   - Planning the #259 visuals would contradict the story ("existing callers keep working") because point (b) deprecates the component. That is a product decision (and an ADR), not a ticket here.
2. **`onReset` does not exist.** AC2 says the reset row "calls `onReset`". Neither `FilterProps` nor `SearchFilterProps` has it (`onReset` exists only on `Calendar`). Today: `Filter` reset = `state.setValue(null)`, which reaches the caller as `onSelectionChange(null)`; `SearchFilter` reset = `onItemSelect(undefined)`. Adding an optional `onReset` is additive and harmless; it is the one real code change the ACs need.
3. **Most of AC2, AC3, AC4 is already implemented and covered, in Playwright CT only.** There is **no Vitest spec and no snapshot-like test** for either component (`find src -name '*.spec.tsx'` shows none in `filter/` or `search-filter/`; the repo has no `__snapshots__`, inline snapshots are stateless because of the dual vitest install, see `UserMenu.spec.tsx`).

## AC by AC against the current code
- **AC1 stories per state.** `Filter` stories: `Uncontrolled` (default), `UncontrolledWithDefault` (active), `WithReset`, `WithoutReset`, `LongLabels`, `Controlled`, `UpdatedWithDateRange`... **No "open" story** (no `defaultOpen`). `SearchFilter` stories: `Basic` (default), `UserSearch`, `Loading`, `ManyUsers`, `Empty`; **no "open" story** (`isOpen` is only an argType) and no explicit "active" one except through `selected` in some stories. **`Filter` has no loading or empty state at all**: its options are a static prop, there is no `isLoading`, and `options=[]` renders an empty popover with no empty text. So "each state for both" is **false for `Filter`** (3 states apply: default, active, open); loading and empty exist only for `SearchFilter` (open question 1). No snapshot test: the closest honest guard is an exact DOM string (ids normalised) as in s05/s06.
- **AC1 tokens.** `filter/index.scss` and `search-filter/index.scss` carry literals: `32px`, `4px`, `1px`, `14px`, `400`/`500`, `6px`, `8px`, `0 6px 0 8px`, `1.25rem` (filter); `240px`, `320px`, `36px`, `240px`, `8px`, `16px`, `32px`, `500` and literal fallbacks `var(--c--globals--spacings--xs, 8px)`, `0.875rem`, `2px` (search-filter). **No `--c--components--filter--*` or `search-filter` variable exists** (0 matches in `cunningham-tokens.css`; no `tokens.ts` in either folder; `cunningham.ts` has no entry). Colours already use contextual tokens everywhere (no hex). Fix = the s06 pattern: `tokens.ts` per component holding the literals (exact current values, so the computed CSS is unchanged), stylesheet only `var(--c--components--...)`, six theme blocks regenerated by `yarn build-theme`.
- **AC2 select marks active, reset clears.** Filter: `c__filter__button--active` + `"label : option"` when a selected option exists (CT test "updates the button"); reset row (only if `showReset` and a value) calls `setValue(null)`, keeps the popover open, native button so keyboard operable (CT `filter-reset.spec.tsx`, 4 tests). SearchFilter: active = `isActive ?? !!activeLabel`; reset row shown only when `showReset && selected` (note: a caller passing `activeLabel` but not `selected` gets an active button **without** a reset row, a trap not to change); reset calls `onItemSelect(undefined)`; CT tests cover show/hide/click/keyboard/`showReset={false}`. **Missing: `onReset`** (fact 2).
- **AC3 loading, empty, selection kept while searching.** Loading: `isLoading` replaces the items with a spinner row (CT test). Empty: `emptyState` row **only if the caller passes the prop and `items` is empty**; without it an empty popover shows nothing (silent). Both rows are `ListBoxItem`s, i.e. `role=option`, with hard-coded English `textValue` ("Loading", "Empty") and an unnamed `Spinner` (`div.c__spinner`), no `aria-busy`, no live region: assistive tech hears an option with no name. Fixing needs a locale key in five locales and changes announced output: not a visual change but beyond the ACs, **DEFERRED** (t04). Selection kept while searching: `SearchFilter` owns **no** selection state; `selected`/`activeLabel` come from the caller and `onSearchChange` never touches them, so the AC holds by construction, even when the selected item is filtered out of `items`. The one reset of the search is intended: choosing an item calls `onSearchChange("")`. **Untested**: CT "typing in the search box filters" does not assert the trigger label, so nothing can fail if a future change cleared the selection on search. A guard test is the useful work.
- **AC4 keyboard.** Filter = React Aria `Select` (Enter/Space/ArrowDown open, arrows, Enter select, Escape close, type-ahead). CT tests cover the sub-panel via keyboard and the reset row; **no CT test opens a plain Filter and selects with the keyboard**. SearchFilter: input focused on open (`requestAnimationFrame`), ArrowDown moves to the listbox (CT), Escape closes and restores focus (CT), reset row reachable (CT). Gaps: ArrowDown on the trigger, Enter on an option in `SearchFilter`, Escape from the listbox (not the input; `handleInputKeyDown` is only on the input, RAC `Popover` handles its own dismissal: to be observed by the test, not assumed), Tab order trigger to reset to input.

## Backward-compat surface
Callers pass `label`, `options`, `showReset`, plus any RAC `SelectProps` for `Filter` (`selectedKey`, `defaultSelectedKey`, `onSelectionChange`, `isDisabled`...); `SearchFilter`/`UserSearchFilter`: `label`, `activeLabel`, `isActive`, `selected`, `searchValue`, `onSearchChange`, `items`, `renderItem`, `onItemSelect`, `isLoading`, `emptyState`, `isOpen`, `onOpenChange`, `showReset`, `placeholder`. Class names a consumer may style: `c__filter`, `c__filter__{button,button--active,button__icon,label,item,popover,subpanel}`, `c__search-filter{,__popover,__search,__list,__item,__empty,__loading}`, `c__dropdown-menu*`. The plan changes none and adds one optional prop.

## Complexity re-score
Story says 3. Without the #259 visuals: guards, one additive prop, one token rewrite: **2** (about 4 person-days). With the #259 bar it is a new story of complexity 4 or 5 plus an ADR.

## Traps for implementers
- Filter renders the Select children twice (hidden collection pass), see comments in `Filter.tsx`; anything stateful stays in the parent.
- `FilterResetRow` is rendered **outside** the ListBox on purpose (collection builder drops plain DOM); do not move it.
- `useControllableState` is not used by either component; if ever needed wrap it, never modify.
- Playwright CT cannot drive controlled components from the test file (functions are one-way dispatchers): use the `mount-*.tsx` helpers.
- Two vitest copies: `toMatchInlineSnapshot` is stateless; compare to a literal string.
