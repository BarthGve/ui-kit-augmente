## The structuring facts
1. **The premise is mostly false: the "updated" user menu is already shipped, and the waffle label is already translated.**
   - ui-kit #278 asks for five changes (image read, 1746x988, both windows 272 px wide): (a) app settings button moved into the user menu, (b) colour gradients removed in both windows, (c) scrolling instead of a "See more" button in the app switcher, (d) same horizontal size for both windows, (e) mobile-specific versions removed. Status in the code: (a) **done** (`appSettingsCTA` is the first item; story `RefreshedExample` says "Matches the refreshed design"), (b) **done for the user menu** (no gradient in `_index.scss`), (d) **done for the user menu** (272 px), (e) **not done**: `UserMenuMobile` (full-screen `Modal`) is still the default under the tablet breakpoint (`withMobileView = true`). (b), (c), (d) for the **waffle panel are not in this repo**: the panel is rendered by a remote script in a shadow root.
   - ui-kit #241 (RGAA 7.1, P1): the waffle label is not translated in nl, de, es. Today `components.laGaufre.label` exists, translated, in all five locales (de "Digitale LaSuite-Dienste", es "Servicios digitales de LaSuite", nl "Digitale LaSuite-diensten", fr "Services de la Suite numérique", en "Digital LaSuite services"), and so do the other seven `laGaufre.*` keys. A jsdom run with `<CunninghamProvider currentLocale="de-DE"><LaGaufreV2 data={{services: []}} /></CunninghamProvider>` gives the button `aria-label="Digitale LaSuite-Dienste"` and passes `label` and `headerLabel="Über"` to the widget. `yarn check-locales` could not be run (no `tsx` in the worktree, node_modules is read-only from the base); keys were compared by hand with node: identical sets for `laGaufre` and `userMenu`. There is **no test** that proves it, which is the only thing missing.
2. **The kit cannot deliver the waffle half of #278.** The widget has no width, gradient or scroll option: its config keys are `api, data, background, buttonElement, dialogElement, display, error, fontFamily, headerLogo, headerUrl, position, showMoreLimit, newWindowLabelSuffix, viewMoreLabel, viewLessLabel`, with a hard-coded `width: 340px` and a "view more" toggle (`showMoreLimit || 6`, `viewMoreLabel || "More apps"`). The 272 px, no "See more", scrolling panel of the design is a change in `suitenumerique/integration`, not here. Out of scope; reported.
3. **Provider trap, checked and cleared.** The unwrapped provider (`components/provider/index.tsx`) registers only en-US and fr-FR; the exported `CunninghamProvider` (`provider/Provider.tsx`, what `src/index.ts` ships) adds all five locales through `customLocales={locales}`. So nl, de, es work for consumers and Storybook; a test or a consumer importing `provider/index` directly gets English. Tests must use `Provider.tsx`.
4. **AC1 "snapshot per state" has nothing to hang on today.** No spec exists for `la-gaufre` or `users/menu` (only the CT `e2e/la-gaufre/la-gaufre-v2.spec.tsx`, which loads the **real remote widget over the network**: not reusable under the "no network in tests" interdict). Stories: `LaGaufreV2` has `Default` and `BottomLeft` (both closed); `UserMenu` has eleven stories, all closed, none "open", none "without user" (a `null` user renders nothing). The `isInitialOpen` prop is declared in `UserMenuProps` and **never read**: no story or consumer can start open. Snapshots: inline snapshots are unusable here (two vitest installs, `toMatchInlineSnapshot` has no snapshot state); prior stories (s05, s10, s11) compare the exact DOM string with `toBe` after normalising react-aria ids. Reused here.
5. **AC1 "no literal value in the stylesheet" is false for the user menu.** `users/menu/_index.scss` holds a literal colour (`box-shadow: 0 6px 20px 0 rgba(0, 0, 18, 0.1)`, identical to the `--c--components--modal--box-shadow` value), literal radius (`8px`, and `4px` taken from the spacing token `3xs` with a `4px` fallback), literal spacing (`7px`, `12px`, `8px` offsets, `1px` gaps, `4px` inline padding) and fallbacks such as `var(--c--globals--spacings--xxs, 6px)`. There is **no `--c--components--user-menu--*` token**. `LaGaufreV2` has no stylesheet of its own (its button is the kit `Button`, tertiary); `la-gaufre/index.scss` only overrides the V1 button (`button.lasuite-gaufre-btn`, `!important`).
6. **AC3 keyboard is largely satisfied, with one nuance.** Observed in jsdom (user-event), both desktop popover and mobile modal: Tab reaches the trigger; Enter opens; focus moves into the dialog (`section[role=dialog]`, tabindex -1); Tab walks App settings, Manage account, Logout, Terms link, then **wraps** back to the first (focus is trapped); Escape closes and **focus returns to the trigger**, `aria-expanded` back to `false`. ArrowDown does nothing: the surface is a `dialog` containing buttons, not a `role=menu`, so "traverses" means Tab traversal. Not changed (switching to the menu pattern is a different component and ADR). The waffle panel keyboard is the widget's: reading its source, Escape closes and returns focus to `buttonElement`, Tab is trapped inside, focus goes into the panel on open, `aria-expanded` is set by the widget. The kit's part is the native `<button>` (Enter/Space) and handing the widget `buttonElement`.

## Tokens and contrast (computed from `src/cunningham-tokens.css`, six themes, overlay composited on the surface)
Pairs used by the user menu: text on `background.surface.primary` and on `overlay.primary` (item hover). Lowest values across the six themes: `neutral.primary` 11.46 / 9.87, `neutral.secondary` 6.43 / 5.80, `neutral.tertiary` (icons) 5.36 / 4.83. All text pairs pass 4.5:1, icons 3:1.
Focus ring today: `box-shadow: 0 0 0 1px var(--c--contextuals--border--semantic--neutral--primary)`:

| theme | ring / surface | ring / overlay (item hover) |
|---|---|---|
| default | 5.36 | 4.83 |
| dark | 3.47 | **2.99** |
| dsfr-light | 5.39 | 4.86 |
| dsfr-dark | 3.51 | 3.03 |
| anct-light | 5.40 | 4.87 |
| anct-dark | 3.51 | 3.02 |

So in the `dark` theme the existing ring on a hovered item is **2.99:1 (below 3:1)**, and `border.semantic.brand.primary` is worse on overlay in dark themes (2.98 to 3.03). `content.semantic.brand.tertiary` clears it everywhere (ring/overlay 4.83 to 5.78; ring/surface 5.35 to 6.70) and is the family the Button focus ring fix (s01) settled on. A 1 px ring is also thin. Proposed in the design, applied in t02 with a contrast test (the plan's STOP rule applies if a token other than this one fails).
Shadow/overlay: no global elevation token; `modal--box-shadow` exists as a component token with the exact literal the menu uses.

## Traps and constraints
- `useControllableState` has a known defect: never modify it; neither component uses it. Wrap if ever needed.
- Vitest runs with `TZ=UTC`; react-aria ids look like `«r1»` and `react-aria123-«r2»`: normalise before comparing the DOM.
- The popover and the modal render in a portal on `document.body`: compare `document.body.innerHTML`, not `container`.
- jsdom does not execute `<script src>`; no network happens, `window._lasuite_widget` is just an array. The widget contract is therefore tested against a stub that listens on `buttonElement`.
- `useResponsive` reads `window.innerWidth` (jsdom 1024) against the default theme breakpoints, and 1024 is already at or under the tablet breakpoint: with `withMobileView` left at its default, jsdom takes the **mobile** (modal) path; pass `withMobileView={false}` to get the popover. Observed, not assumed.
- The existing CT `e2e/la-gaufre/` needs the network; do not extend it. `playwright/.cache` must be cleared between CSS mutations.
- `cunningham-tokens-sass.scss` is stale at HEAD: `yarn build-theme`/`build` rewrites unrelated lines. Restore it and hand-add only the new `user-menu` blocks (diff-verified), flagged in the PR.
- Never port 6006; ports from `bash .dm/lib/dm-port.sh`; no broad `pkill`.
- ADRs: none needed (no dependency, no structural decision; component tokens follow ADR 002).
