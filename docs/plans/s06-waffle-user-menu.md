# Plan — Story s06-waffle-user-menu

Branch: `feature/s06-waffle-user-menu` (framing) · ticket: `feature/s06-waffle-user-menu/<ticket-id>`
Research: `docs/research/s06-waffle-user-menu.md` — read it first. Design: `docs/designs/s06-waffle-user-menu.md`.

## Target story
**As a** user of La Suite **I want** the updated app switcher and user menu **so that** I move between applications consistently. Complexity 2 in stories.md, **3 after research**.
**The premise is mostly false.** The refreshed user menu of ui-kit #278 is already shipped (App settings inside, 272 px, no gradient) and the waffle label of #241 is already translated in all five locales. What is genuinely missing: the per-state stories and DOM tests (AC1), the tests proving the label and the keyboard contract (AC2, AC3), the tokens (the user menu stylesheet holds literal colour, radius and spacing, and a 2.99:1 focus ring in `dark`), and #278's removal of the mobile layout. The waffle panel's width, scroll and "See more" belong to the remote widget (`suitenumerique/integration`), not to this repo.

Acceptance criteria (docs/stories.md), as reinterpreted:
- AC1 `LaGaufreV2` (closed, open) and `UserMenu` (closed, open, without user) each have a Storybook story per state, covered by a DOM test (exact-string comparison; inline snapshots are unusable here), and colour, spacing and radius in the user menu stylesheet come from tokens (no literal). `LaGaufreV2` has no user and no stylesheet of its own.
- AC2 `components.laGaufre.label` is translated in de-DE, es-ES, nl-NL and fr-FR (not the English text) and reaches the button and the widget in each locale.
- AC3 Keyboard opens, traverses (Tab, trapped, wraps) and closes (Escape, focus returns) the user menu; the waffle button opens through the keyboard and hands the widget its `buttonElement` (the panel's own keyboard is the remote widget's, read in its source, not testable offline).
