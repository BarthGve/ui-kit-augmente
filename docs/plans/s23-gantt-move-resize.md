## Target story
**As a** project manager **I want** to move and resize task bars **so that** I reschedule directly on the chart. Complexity 4 in stories.md, 4 after research (calendar edit rules, a pointer+keyboard session, a11y, real-browser auto-scroll/touch; no dependency, two new props). Dependency: s22 (merged). Blocks s24.
Premises checked against the code: "no equivalent" n/a (extends s22); **false/partial: the pixel-to-date inverse and `snap` were "reserved" by s22 but not shipped** (t01 writes them); `components/dnd/` and `@dnd-kit` **do not fit** (no resize, no Alt/Shift chords, fixed-pixel snapping, imposes `role=button` on an `aria-hidden` bar): native pointer events, **no dependency, no ADR needed** (ADR 005 stays free).
Acceptance criteria (docs/stories.md):
- AC1 Dragging a bar changes start and end by the same amount, and `onTaskChange` is called with the new dates.
- AC2 Dragging a bar edge changes only that date, and a task cannot end before it starts.
- AC3 Same from the keyboard: with a task focused, Alt+Left/Right move by one zoom unit, Shift+Left/Right change the end by one zoom unit, Escape cancels a change in progress.
- AC4 Dropping or resizing snaps to the current zoom unit (day, week or month).
- AC5 Escape during a drag cancels it and restores the original dates.

## Lessons carried from s22 (apply in every ticket)
- Vitest runs `TZ=UTC` suite-wide: any time-zone claim needs a child-process test with a real `TZ`.
- Data-controlled sizes stay bounded (`MAX_DAYS`): an edit may not produce an unbounded axis; clamp to the axis.
- Contrast is tested in all six themes for every new colour pair, with the emitted variables.
- `useControllableState` has a defect in uncontrolled-with-callback mode: wrap or avoid (avoided here).
- Mutation-test the guards (what the ticket relies on must turn a test red when removed) and report them.
- jsdom has no layout: real pointer, drag, scroll, auto-scroll and focus go to Playwright CT (chromium).
