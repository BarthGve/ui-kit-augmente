# Design System — ui-kit-augmente

Source: the existing ui-kit design system (`@gouvfr-lasuite/ui-components` 1.3.0, `@gouvfr-lasuite/ui-tokens` 3.2.0). Nothing here is invented: values were read from `packages/ui-components/cunningham.ts` and the generated `packages/ui-components/src/cunningham-tokens.ts` on 2026-10-09. A need that this system does not cover is a "design system gap" to report, never to fill freestyle.

**Warning — two sets of defaults.** `packages/ui-tokens` holds Cunningham's own defaults (blue brand `#1167D4`, Roboto Flex). The effective theme of `ui-components` overrides them (violet brand, Hanken Grotesk). Use the `ui-components` values below. The design-system artifact (https://claude.ai/artifact/XF7u4R6KevkT1uErAcxGfP) is a visual reference only and must follow this document.

## Tokens
Tokens are CSS variables `--c--<group>--<name>`, generated by `yarn build-theme`. Always reference a token; never write a literal value.

### Themes
Six themes are generated: `default` (white label, light), `dark`, `dsfr-light`, `dsfr-dark`, `anct-light`, `anct-dark`. A new component must render correctly in all of them, which is guaranteed by using only contextual tokens (`contextuals.*`) rather than the colour scales.

### Contextual tokens (what components consume)
Three groups, each with a `semantic` set of roles (`brand`, `neutral`, `info`, `success`, `warning`, `error`, `disabled`, `contextual`, `overlay`):
- `contextuals.background.surface.{primary,secondary,tertiary}` — light: `#FFFFFF`, `#FFFFFF`, `#F8F8F9`; dark: `#2F303D`, `#25252F`, `#1B1B23`. `contextuals.background.semantic.<role>.{primary,secondary,tertiary}` plus `-hover` variants.
- `contextuals.content.semantic.<role>.{primary,secondary,tertiary,on-<role>}` — for example neutral: `#25252F`, `#5D5D70`, `#69697D`, on-neutral `#F0F0F3`; error: `#910C06`, `#C00100`, `#D7010E`.
- `contextuals.border.surface.primary` (`#E2E2EA` in light) and `contextuals.border.semantic.<role>.*` — brand: `#5E5CD0`, `#A0A5F6`, `#CED3F1`.

### Spacing, radius, breakpoints, motion
- Spacings: `4xs` 0.125rem · `3xs` 0.25rem · `2xs` 0.375rem · `xs` 0.5rem · `sm` 0.75rem · `base` 1rem · `md` 1.5rem · `lg` 2rem · `xl` 2.5rem · `xxl`/`2xl` 3rem · `xxxl`/`3xl` 3.5rem · `4xl` 4rem · `5xl` 4.5rem · `6xl` 6rem · `7xl` 7.5rem · `bx` 2.2rem.
- Radius is a component token, not a global: Button 4px; Input, Select, DatePicker 8px (2px or 4px on hover/focus); Modal and Calendar 8px; Badge 12px; DataGrid 4px; Tooltip 0.5rem.
- Breakpoints (effective): `xxs` 320px · `xs` 480px · `mobile` 768px · `tablet` 1024px (the default theme also keeps `sm` 576, `md` 768, `lg` 992, `xl` 1200, `xxl` 1400).

- Button heights: medium 40px, small 32px, nano 24px.

## UI patterns
- **Forms:** every field goes through `Field`/`LabelledBox`: label, optional hint text (`text`), right text (`rightText`), and a state `default | error | success`. Prefer `floating` for dense forms, `classic` for long forms, `inline` for label-beside-field rows. `fullWidth` stretches the control. Errors are shown as text below the field, never colour alone.
- **States:** loading uses `Loader`/`Spinner` (a `Skeleton` is planned, s09); empty states use the `DataGrid` empty state with a decorative image; disabled uses the `disabled` contextual tokens; error and success use the `error` and `success` roles.
- **Feedback:** transient confirmation → `Toast` (via `ToastProvider`); persistent page message → `Alert`; blocking decision → `ConfirmationModal` / `DeleteConfirmationModal`; informative text on hover or focus → `Tooltip`.
- **Accessibility:** the system targets RGAA; interactive elements are built on React Aria primitives; every control is keyboard operable with a visible focus ring; icon-only controls have an accessible name; colour is never the only signal.
- **i18n:** user-visible text lives in `src/locales/*.json` (five locales), never inline.
- **Design reference:** the approved designs for most stories are those of the linked ui-kit issues; for components without one, the design is produced at `/dm-design` and reviewed before planning.

## Do / Don't
- ✅ Use contextual tokens (`contextuals.*`) so a component works in all six themes.
- ✅ Use `--c--components--<component>--<property>` variables for component-specific values, declared in `cunningham.ts`.
- ✅ Compose with the components above; extend through props or a documented variant.
- ✅ Check light and dark, and at least the `default` and `dsfr-light` themes, in Storybook.
- ✅ Give every icon-only control an accessible name.
- ❌ Never write a literal colour, spacing, radius or font in a stylesheet.
- ❌ Never take values from `packages/ui-tokens` defaults (blue / Roboto): the effective theme is in `ui-components`.
- ❌ Never invent a component or a token outside this system; report the gap.
- ❌ Never rely on colour alone, or use emoji as icons.
- ❌ Never edit the generated `src/cunningham-tokens.*` files.
